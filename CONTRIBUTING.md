# Contributing

Thank you for your interest in improving this project. Bug reports, corrections and improvements are welcome.

## Reporting issues

Before opening an issue, search the existing issues to avoid duplicates. When you open one, include:

- What you expected to happen and what happened instead
- Steps to reproduce the problem
- Relevant details such as your operating system, tool versions and AWS Region

For security issues, follow [SECURITY.md](SECURITY.md) instead of opening a public issue.

## Submitting changes

1. Fork the repository and create a branch from the default branch.
2. Keep each pull request focused on a single change.
3. Follow the existing style and structure of the files you edit.
4. Test your change before submitting it.
5. Write a clear commit message that explains what changed and why.
6. Open a pull request that describes the change and links any related issue.
